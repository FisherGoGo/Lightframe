## 1. 需要什么界面

| 区域 | 内容 | 实现阶段 |
|---|---|---|
| 取景器 | 显示照片纹理，保存实际显示矩形 | 基础版本 |
| 焦距 | 24/35/50/85 mm 预设，当前值 | 基础版本 |
| 曝光 | 光圈、快门、ISO，当前曝光倍率 | 曝光完成后 |
| 对焦 | 距离输入、点击对焦标记 | 深度完成后 |
| 拍照 | 按钮、进度、结果路径、错误信息 | 保存完成后 |
| 实验与调试 | 场景、时间暂停/复位、效果开关、深度与 CoC 图 | 分阶段加入 |

表中阶段表示功能控件的接入时机。P03～P09 使用现有标准 ImGui 面板；参考图的黑白分格、字体、图标、叠加布局及可开关调试入口集中到 P10，不作为前面功能任务的完成条件。

尚未实现的效果不显示为可用功能。比如只有曝光时，应说明光圈暂时只影响亮度，景深将在后续加入。

## 2. 参数控件怎么实现

- 焦距用 mm，对焦距离用 m，光圈显示 f/4 等格式。
- 快门内部保存秒，UI 用常见档位或分数显示，避免整数除法得到零。
- ISO 可以先提供 100、200、400、800 等预设。
- 参数编辑后统一校验，再传给 Camera、PostProcess 和 Capture。
- 机位复位与摄影参数复位分别提供；实验预设可以同时恢复两者。
- 对焦标记属于 UI 叠加层，默认不写进照片。
- 拍摄状态防止重复启动任务；可以允许调整预览参数，但当前拍照必须使用固定快照。

需要共享 `ViewportRect`：包含照片显示位置、大小和纹理方向。鼠标点击通过它换算到照片坐标，不能根据整个窗口尺寸猜测。

## 3. 三个实验预设

每个预设固定场景 ID、对象与灯光配置、相机姿态、摄影参数、动画起始时间、随机种子、图像尺寸及算法设置，并提供“一键复位”。对照照片只改该实验指定的变量。目标版本通过内置预设恢复实验，不要求先实现通用 JSON 导入。

### 实验 A：变焦与移动

固定机位拍 24 mm 和 85 mm，观察取景范围变化。再移动机位保持主体画面大小近似一致，比较主体与背景关系。

预设保存初始相机姿态、场景和参数，提供机位复位。讲解时区分原地变焦和为保持构图而移动机位产生的透视变化。

阶段 C 补充曝光对照：静态场景中关闭景深与噪声，固定机位、灯光和光圈，比较快门或 ISO 翻倍以及两者互相补偿。导出对应照片，同时记录色调映射前固定区域的平均线性亮度。

### 实验 B：对焦与景深

前景主体与远背景分开摆放，固定机位和焦距；先对焦主体，再对焦背景。比较 f/2 与 f/8，并用快门或 ISO 补偿曝光。

例如 f/2、1/500 s、ISO 100 与 f/8、1/31.25 s、ISO 100 在相对模型中等曝光。实际 UI 采用常见 1/30 s 档位时只有近似相等，数值检查时使用精确值。

使用静态场景并关闭噪声，分两组拍摄：第一组只改变对焦距离；第二组固定对焦距离，改变光圈并用快门补偿曝光。初始可用 85 mm、主体轴向 1 m、背景 5 m，使虚化明显；另保留 50 mm、f/4、对焦 5 m、物体 10 m 的 CoC 数值检查，避免将视觉强度当成公式正确性的唯一依据。

### 实验 C：冻结、拖影与噪声

分两组验证，再做综合展示：

- C1 拖影：关闭噪声和景深，固定相机、光圈、运动轨迹和起始时间，只改变快门并用 ISO 补偿曝光。可比较 1/1000 s、ISO 3200 与 1/31.25 s、ISO 100；按画面像素位移选择速度与 K，确保物体在曝光期间不出画。
- C2 噪声：使用静态场景，关闭景深，固定种子，以 1/1000 s、ISO 800 与 1/125 s、ISO 100 保持等曝光，比较同一平坦区域的颗粒。保留一张关闭噪声的参考图，避免把纹理细节当作噪声。

两组均通过后，可开启噪声拍摄运动物体，综合展示短快门、高 ISO 与长快门、低 ISO 的效果。综合展示不能替代分别验收。

预览标明“运动模糊在拍照时计算”，避免用户把瞬间预览当作最终长曝光结果。

## 4. 怎样判断实现正确

| 项目 | 检查方法 | 预期 |
|---|---|---|
| 相机移动 | 在无卡顿限幅触发时，以 30/60/120 FPS 执行同样的 2 s 移动输入 | 相对位移差不超过 2%；记录实际输入持续时间 |
| 焦距 | 固定机位切换预设 | 主体大小与取景范围改变，机位不变 |
| 深度 | 点击已知轴向 2/5/10 m 的正对相机平面内部，避开轮廓 | 绝对误差不超过 0.01 m；背景保持原对焦值 |
| 曝光 | 静态场景关闭景深、噪声，在非零固定区域比较快门或 ISO 翻倍 | 色调映射前平均亮度倍率为 2，偏差不超过 1% |
| 等曝光 | 同上，快门减半同时 ISO 翻倍 | 平均线性亮度相对差不超过 1% |
| CoC | 50 mm、f/4、对焦 5 m、轴向 10 m，图像高 600 px | 未截断半径约 0.789 px，绝对误差不超过 0.01 px |
| 景深 | 固定构图，改变对焦层 | 清晰区域随对焦层移动 |
| 光圈 | 补偿亮度后增大孔径 | 离焦区域更模糊 |
| 时间采样亮度 | 静态场景关闭噪声，同快照比较 K=1/16/64 | 平均线性亮度相对差不超过 1% |
| 时间采样质量 | 运动场景关闭噪声，同快照比较 K=16/64 | 对照拖影连续性并记录重影；不要求移动物体的每个像素亮度相同 |
| 噪声 | 同一构建与设备，固定种子重复拍照；对照关闭噪声的参考图 | 解码像素可复现；静态等曝光平坦区域的噪声残差标准差随 ISO 提高而增大 |
| 导出 | 打开 PNG 并检查对应 JSON | 不含 UI，参数匹配 |

这些是实现后的手工验收项目，不代表当前已有测试结果。最初先留截图和参数记录；曝光倍率、FOV 和深度重建等纯数学函数稳定后，可补少量数值测试。

数值检查固定 900 × 600、near=0.1 m、far=100 m，使用同一构建和设备。线性亮度检查读取曝光后、噪声与色调映射前的数据，选择参考值明显大于零的区域；不要直接比较 PNG 值。纯公式可用独立计算值验证，GPU 流程以浮点读回确认。

性能初始目标：在待确认的演示设备上，900 × 600、景深 24 样本、半径上限 24 px 时，预览帧时间 P95 不超过 33.3 ms；K=32 的拍摄从请求到 PNG 与 JSON 保存完成不超过 5 s。预热后记录 10 s 预览和至少 5 次拍摄，注明垂直同步、设备、算法设置及保存位置。上述目标需实测确认；不达标时先分析耗时，再调整样本数或算法并重验图像质量，不能静默降低照片尺寸或修改物理公式。

## 5. 需要记录什么

每个阶段记录：完成的功能、演示截图、使用参数、算法设置、已知问题。性能至少分别测预览帧时间和拍照耗时，并注明设备、分辨率、景深样本数和时间样本数。

报告明确区分：教程基础代码、外部模型与贴图、自行实现的摄影参数和成像算法。景深边缘近似、非真实传感器噪声、预览没有运动拖影，都需要如实说明。

### 7.2 本项目怎样借鉴页面

目标是让用户保持构图时完成参数操作，并立即看见已实现效果的变化。目标版本的正常摄影界面以取景器为主体，不长期展开全部调试控件。

| 区域 | 本项目建议 | 对应职责 |
|---|---|---|
| 取景画面 | 保持真实 3:2 照片比例，窗口不匹配时留边；可切换三分网格 | 显示照片纹理，维护 ViewportRect |
| 对焦反馈 | 中心对焦框或点击位置标记；显示对焦距离，背景测距无效时给出提示 | 发出测距请求，成功后更新参数 |
| 参数区 | 沿画面边缘集中排列焦距、光圈、快门、ISO；选中项使用稳定高亮，明确单位 | 读写同一 CameraSettings |
| 状态区 | 显示 M、AF/MF、照片尺寸和拍摄进度；仅显示已实现的状态 | 反映当前参数和 Capture 状态 |
| 操作提示 | 首次进入时显示必要按键，熟悉后可收起；解释当前选中参数 | UI 自身状态，不进入照片 |
| 实验面板 | 单独打开实验预设、复位、深度和 CoC 调试；默认收起 | 演示、验证和故障定位 |
| 拍后反馈 | 显示刚完成的照片缩略图与保存结果，允许返回取景 | 使用完成后的照片及快照元数据 |

P03～P09 继续使用现有 ImGui 标准控件，以参数编辑、读数和调试为主；P10 再通过无边框窗口、文本和绘制接口组织摄影界面，原调试面板保留为可开关入口，两种展示共用参数与请求。不要加入没有功能意义的电量、存储卡等装饰状态。白平衡、滤镜、闪光灯属于后续选做项，未实现时不展示为可操作参数。

### 7.3 PC 操作建议与输入分配

下表是本项目的统一键位建议，保留 01 中“右键观察、左键对焦”的规则。游戏手柄的半按/全按体验在 PC 上拆成独立动作，不要求普通鼠标模拟压力。

| 操作 | 建议输入 | 生效条件 |
|---|---|---|
| 移动与观察 | WASD；在取景器内按住右键转向 | 无文本编辑或弹窗占用输入 |
| 变焦 | 在取景器内滚轮 | 未按住右键，未悬停参数控件 |
| 选择参数 | 左/右方向键，或点击参数项 | 摄影界面有效且无文本编辑 |
| 调整参数 | 上/下方向键；悬停参数项时滚轮 | 改变选中参数的档位 |
| 点击对焦 | 在取景器内左键 | D 阶段后，无覆盖控件且未处于观察拖动 |
| 中心对焦 | F | D 阶段后，复用中心像素测距 |
| 手动对焦 | 选择对焦距离并调整 | 显示 MF；只有有效测距才切回 AF |
| 拍照 | Enter 或拍照按钮 | C 阶段后，Capture 非忙碌 |
| 网格与实验面板 | G 切换网格；Tab 打开/收起实验面板 | 对应功能接入后 |

同一输入事件只能消费一次：文本编辑/弹窗 → 被命中的参数控件 → 取景器 → 其他快捷键。滚轮操作参数时不能同时变焦；右键转向时不能触发点击对焦。方向键和 Enter 按下沿触发，避免每帧改档或重复拍摄。网格和参数高亮仅属于 UI。

App 负责上述输入优先级与取景器命中判断，允许移动/观察时才转发给 CameraController；UI 接管观察时先释放光标。CameraController 只负责机位操作与鼠标观察状态，参数编辑、对焦和拍照请求继续由 App 协调。P03 已接入 UI 捕获、真实取景矩形、右键观察和滚轮变焦分流；方向键选档、对焦、拍照、网格和可收起实验面板仍属于后续计划。

第一轮不必增加“步行/举起相机”两套操作模式，直接进入取景即可。相机举起动画、手柄压力输入、蹲下与侧倾、实体机身外观均为选做项；它们不阻塞摄影参数与保存流程。

### 7.4 参数学习与拍摄反馈

参数说明紧跟选中项，使用短句解释当前版本实际效果，例如：“焦距增大，取景范围缩小”“大光圈使离焦区域更模糊”“长快门拖影在拍照后显示”。阶段 C 的光圈说明应标注“目前只影响曝光”。

M 模式作为目标版本基础。A/S 模式需要测光、自动参数求解和越界提示，属于加分功能；不能只增加模式标签或自动调整屏幕亮度。实现条件见 02。

拍照流程沿用 06 的状态：开始时固定快照；采样期间显示进度并阻止重复拍摄；保存完成后显示缩略图与文件位置；保存失败显示具体原因。缩略图和参数摘要必须对应该次快照，而不是当前已修改的预览设置。

### 7.5 实现顺序与交互验收

前面阶段先用标准控件落实功能和必要输入隔离；正式 HUD 的外观与导航整理集中到 G / P10。以下不是要求每个功能阶段同时制作摄影界面。

| 阶段 | 增加的交互 | 检查证据 |
|---|---|---|
| B | 3:2 取景器、标准焦距控件及其选中状态、变焦与参数操作分流 | 滚轮变焦不移动机位；操作参数不误触相机 |
| C | 光圈/快门/ISO 档位、拍照反馈、界面与导出分离 | 界面值与 JSON 一致；PNG 无网格和参数 |
| D | 点击/中心对焦、手动距离、对焦反馈 | 缩放和留边后测距位置正确；背景不伪报对焦成功 |
| E/F | 拍摄进度、长曝光说明、实验面板 | 连按拍照只启动一次；拍摄中改预览不污染结果 |
| G | 摄影 HUD 样式与叠加布局、调试面板开关、提示收起、导航和输入状态整理，再汇总验收与打包 | HUD 与调试控件共用参数；UI 不进照片；缩放/对焦命中正确；编辑无误触；返回取景无跳转 |

另外验收：收起实验面板不改变摄影参数；窗口变化不改变照片构图；焦点丢失时终止观察拖动并清除持续按键状态。横竖拍若以后加入，应同步变更传感器方向、投影、成像尺寸与保存元数据，不能只旋转 UI 或裁切显示。

2025 年的 PS5 评测曾记录长曝光照片视场角与所选镜头不一致，以及竖拍分辨率没有对应翻转的问题；这不是对当前 PC 版本的结论。本项目将其转化为检查项：长曝光仍使用固定快照投影，导出尺寸与实际构图一致。[评测中的版本记录](https://www.thefourthfocus.com/post/lushfoil-photography-sim-review)
