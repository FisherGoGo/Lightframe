# 02 相机与摄影参数

[返回总览](00-项目总览与开发顺序.md)

Camera 负责机位和矩阵，CameraSettings 保存摄影参数。相机参数影响渲染，但 Camera 本身不负责遍历像素、执行模糊或写 PNG。

阶段安排：A 完成机位与矩阵，B 完成焦距，C 让光圈、快门和 ISO 参与曝光，D 加入点击对焦和景深。参数已出现在结构体里不代表对应效果已经实现。

## 1. 保存哪些数据

```cpp
struct CameraSettings {
    float focalLengthMm = 50.0f;
    float sensorWidthMm = 36.0f;
    float sensorHeightMm = 24.0f;
    float apertureFNumber = 4.0f;
    float shutterSeconds = 1.0f / 125.0f;
    float iso = 100.0f;
    float focusDistanceM = 5.0f;
};
```

Camera 另外保存 `position`、`yaw`、`pitch`、由角度计算出的 `front/right/up`，以及移动速度、鼠标灵敏度、近远裁剪距离。裁剪距离的初始建议为 0.1 m 和 100 m，之后按场景范围调整。

焦距决定取景范围，对焦距离决定哪层清晰。不要用一个变量表达两者。FOV 从焦距计算，不能再独立保存一个会与焦距冲突的 Zoom 参数。

## 2. 如何计算观察矩阵

先沿用教程的角度和方向计算：

```cpp
front.x = cos(glm::radians(yaw)) * cos(glm::radians(pitch));
front.y = sin(glm::radians(pitch));
front.z = sin(glm::radians(yaw)) * cos(glm::radians(pitch));
front = glm::normalize(front);
right = glm::normalize(glm::cross(front, worldUp));
up = glm::normalize(glm::cross(right, front));
view = glm::lookAt(position, position + front, up);
```

约定 `worldUp = (0,1,0)`，初始 yaw 为 -90° 时朝向 -Z。将 pitch 限制在约 -89°～89°，避免方向与世界上方平行时叉积退化。矩阵与移动方式可参考 [LearnOpenGL Camera](https://learnopengl.com/Getting-started/Camera)。

键盘先组合移动方向，对非零方向归一化，然后乘 `speed * dt`；这样同时按前进和右移不会比单方向更快。首版允许自由飞行和穿过物体，无需碰撞系统。

## 3. 如何从焦距生成投影矩阵

```cpp
float fovY = 2.0f * std::atan(
    settings.sensorHeightMm / (2.0f * settings.focalLengthMm));
float aspect = settings.sensorWidthMm / settings.sensorHeightMm;
glm::mat4 projection = glm::perspective(fovY, aspect, nearM, farM);
```

`atan` 的结果已经是弧度，不要再做一次角度转弧度。36 × 24 mm 传感器、50 mm 焦距的垂直视场角约为 27°，可用作初始检查。

窗口宽高比不用于这个照片投影矩阵。先渲染 3:2 照片，再放进窗口中显示；展示区域比例不符时留边。

原地改 24 mm → 85 mm，只修改投影，不修改 position。向前移动只修改 position，两种操作需要分开演示。

## 4. 建议提供什么接口

```cpp
// 接口草案，非完整类声明
glm::mat4 viewMatrix() const;
glm::mat4 projectionMatrix(const CameraSettings& settings) const;
void move(glm::vec3 direction, float deltaSeconds);
void rotate(float deltaX, float deltaY);
void resetPose();
```

由统一的参数校验函数保证焦距、f 值、快门和 ISO 大于零，`near > 0`、`far > near`，对焦距离转换为 mm 后大于焦距。可先给 UI 一组合理范围，范围属于产品约束，不是镜头物理定律。

目标版本建议范围：焦距 24～85 mm、光圈 f/1.4～f/16、快门 1/1000～1/4 s、ISO 100～3200、对焦距离 0.5～50 m。拒绝 NaN 和无穷值；数值输入、预设和未来的配置导入共用校验。该范围不保证所有运动在固定样本数下都能平滑成像，拖影实验仍需单独固定速度与采样设置。

## 5. 点击对焦怎么做

这项功能需要 Renderer 的深度纹理，基础 Camera 完成后再做：

1. 判断点击是否落在真实照片显示矩形里，排除面板和留边。
2. 将点击位置换算为照片的 `(u,v)`，再换成深度纹理像素。
3. 按纹理显示的方向处理 Y 翻转，不能重复翻转。
4. 从场景 FBO 读取该像素深度，按 05 中公式恢复正轴向距离。
5. 深度为背景清除值时保持原值，否则写入 `focusDistanceM`。

只在点击时读回一个像素，避免每帧 GPU 同步。初期可以由 App 协调：UI 产生点击请求 → Renderer 返回测距 → 更新 settings。Camera 不需要持有 FBO。

## 6. 完成条件

- 机位移动、转头、复位工作正常；帧率变化不改变移动速度。
- 不同焦距能改变取景范围，且相机位置保持不变。
- 调对焦距离不会改变焦距或机位。
- 对已知轴向距离为 2、5、10 m 的物体，点击读数正确。
- 参数无重复来源，界面和渲染读取同一份设置。

第一阶段只做位置、转向、矩阵和焦距；摄影参数先保存，效果在后处理模块逐项加入。

## 7. 从摄影游戏交互转化的参数规则

配合 [07 的 Lushfoil 调研与交互方案](07-界面与验收.md)，参数既支持鼠标编辑，也支持方向键逐档调整。以下是本项目建议，具体档位不表示游戏使用同一组值。

- 光圈可提供 f/1.4、f/2、f/2.8、f/4、f/5.6、f/8、f/11、f/16。
- 快门可提供 1/1000、1/500、1/250、1/125、1/60、1/30、1/15、1/8、1/4 s，始终保存浮点秒数。
- ISO 可提供 100、200、400、800、1600、3200；焦距继续提供 24/35/50/85 mm 和范围内连续变焦。
- 对焦距离按 m 保存，可采用非线性步进以方便近处微调；不能以“变焦”代替手动对焦。
- 标准档位通常是取整值，数值验收仍允许输入精确值。UI 档位索引不成为另一份摄影参数；参数值是唯一来源，从精确输入开始步进时选相应方向的相邻档位。

点击对焦与 F 键中心对焦共用深度读取和距离重建。成功后更新对焦距离并显示 AF；编辑距离显示 MF。这里的 AF 是一次测距对焦，不声称支持持续追焦或真实镜头伺服模拟。标记超时、当前选中项与 AF/MF 提示由 UI 保存。

M 模式使用用户设置的光圈、快门和 ISO，是目标版本必做范围。A/S 模式为加分项：先测量有效画面区域的线性亮度，使用项目内部标定的曝光目标，再求解自动参数。第一轮可固定用户 ISO，在 A 模式下固定光圈、解快门，在 S 模式下固定快门、解光圈；用 EV 补偿修正目标曝光。求解结果必须通过统一范围校验，无法达到目标时显示欠曝/过曝提示，并在界面区分手动项和自动项。

A/S 是基于本项目相对曝光模型的控制器，不代表真实相机测光系统。自动结果应体现在 CameraSettings 中并进入拍摄快照；保存 JSON 时同时记录模式、EV 与实际使用值。模式与 EV 仅在该扩展实现后加入结构体。增加自动模式后单独验证动态稳定性、参数边界和预览/照片一致性。
