# 01 工程与主循环

[返回总览](00-项目总览与开发顺序.md)

这一部分负责让各模块在正确的时机运行。建议由 `App` 管理窗口、模块生命周期和主循环。

阶段安排：A 完成工程与输入，B 接入最小 UI，C 接入单帧保存，E 再加入拍照任务推进。下面的完整主循环是最终组织参考，不要求阶段 A 一次写完。

## 1. 需要实现什么

| 功能 | 实现方法 |
|---|---|
| 创建窗口与上下文 | GLFW 创建 OpenGL 3.3 Core 上下文，然后加载 GLAD |
| 初始化资源 | 创建着色器、几何体、相机、渲染目标，之后加入 UI |
| 每帧更新 | 计算时间差、收集输入、更新参数、渲染、交换缓冲 |
| 输入协调 | 将移动输入交给 Camera，将界面交互交给 UI |
| 资源路径 | 使用明确的资源根目录，构建时复制资源或传入路径 |
| 正常退出 | 在 OpenGL 上下文销毁前释放纹理、缓冲、程序与 UI |
| 错误提示 | 输出窗口创建、着色器编译、资源加载和保存错误 |

## 2. 第一个版本怎么搭

先复用能运行的课程工程，确认三角形显示正常，再整理为 CMake 工程。不需要在第一天接入所有库；窗口、GLAD、GLM 足够开始。

初始化顺序：

```text
初始化 GLFW → 设置上下文要求 → 创建窗口
→ 将上下文设为当前 → 加载 GLAD
→ 查询实际版本 → 创建 OpenGL 资源 → 进入主循环
```

任何关键步骤失败都应退出并给出原因。着色器错误需要显示完整编译或链接日志，不能只写“渲染失败”。GLAD 的具体加载接口以采用的生成版本为准。

阶段 A 同时记录操作系统、编译器、CMake、依赖版本与获取方式、显卡和驱动、构建及启动命令。优先选一种依赖管理方式；首次获取依赖可以联网，交付包启动不应临时下载资源。演示设备尚未确定时，将兼容性验收标为待验证。

## 3. 主循环怎样组织

以下为流程伪代码，`renderPreview` 等接口需要后续实现：

```cpp
while (!windowShouldClose()) {
    pollEvents();
    const double now = getTime();
    const float dt = float(now - previousTime);
    previousTime = now;

    ui.beginFrame();
    ui.editSettings(settings);       // 同一帧使用修改后的参数
    handleInput(camera, settings, dt);

    if (ui.requestedCapture() && !capture.isBusy())
        capture.start(makeSnapshot());

    capture.advance(renderer, postProcess, scene);
    renderer.renderPreview(scene, camera, settings, sceneTime);
    presentPhoto();
    ui.render();
    swapBuffers();
}
```

初期没有 UI 或 Capture 时，直接省略对应步骤。程序卡顿后可以限制用于移动的 `dt`，防止恢复窗口时相机突然跳很远；场景时间和拍照采样时间仍使用明确的时间定义，不依赖这个移动限幅。

Scene 提供 `evaluateAt(time)`，Renderer 在预览时间或拍照样本时间调用它，不能只靠每帧累加物体位置。

## 4. 输入如何分配

- WASD：前后左右移动；需要时加上下移动按键。
- 按住右键且鼠标位于取景器：旋转观察方向。
- 松开右键：正常操作参数面板。
- UI 捕获键盘时，不处理相机移动；UI 捕获鼠标时，不触发相机转动或点击对焦。
- 从面板进入观察模式时重置上次鼠标位置，第一条移动事件只建立基准。
- 若取景器嵌在 UI 窗口中，需要专门判断它是否悬停、是否有弹窗覆盖，不能仅依赖一个全局鼠标捕获标志。

GLFW 回调只记录事件或转发给输入层，不建议在鼠标回调里执行完整渲染或保存文件。

摄影界面完整键位见 [07 的 PC 操作建议](07-界面与验收.md)。在该界面接入后，将滚轮、方向键、F 和 Enter 转为变焦、参数编辑、中心对焦和拍照请求。每条事件只能消费一次；UI 文本编辑和弹窗优先，其次是被命中的控件和取景器。连续移动使用按住状态，改档与拍照使用按下沿。窗口失去焦点时清除持续输入与观察拖动，重新进入观察时重置鼠标基准。

## 5. 窗口尺寸和高 DPI

窗口逻辑尺寸、实际 framebuffer 像素尺寸、照片纹理尺寸是三个数。显示时根据 framebuffer 尺寸设置 viewport；鼠标位置按照取景器实际矩形换算到照片像素。

窗口最小化导致 framebuffer 为零时，跳过显示渲染，不创建零尺寸 FBO。首版可以固定照片为 900 × 600 等 3:2 尺寸，窗口缩放只改变显示大小。

## 6. 完成条件

- 能从干净构建目录编译、启动、退出。
- 从不同工作目录启动仍能找到着色器和资源。
- 修改窗口尺寸、最小化、恢复不会崩溃。
- 资源加载失败时能知道具体文件和原因。
- 退出时 OpenGL 资源在上下文仍有效时释放。
