# 01 工程与主循环

[返回总览](00-项目总览与开发顺序.md)

这一部分负责让各模块在正确的时机运行。P01 已由 `App` 管理窗口、模块生命周期和主循环，P02 已接入 Camera、Scene 与键鼠输入，2026-10-13 已将相机操作抽入 CameraController，P03 已接入 CameraSettings、最小 UI 和取景矩形；后文的完整拍摄流程仍为计划。

当前 `main.cpp` 解析自检开关后调用 `App::run(bool smokeTest)`。App 顺序执行 `initialize()` 和 `renderLoop()`：轮询事件、计算时间差，普通模式建立 UI 帧并编辑 settings、执行复位请求、分配输入，随后绘制场景、合成 UI 和交换缓冲。CameraController 先轮询鼠标差值并转向，再组合 WASD/QE 移动。ImGui GLFW 后端接收全部键鼠事件，并串接 App 的失焦释放回调；App 在 UI 帧内按下沿处理右键进入和 R 复位，根据捕获状态、取景矩形和当前观察状态允许机位输入；右键释放通过 GLFW 当前状态处理。观察时 UI 禁用鼠标命中，避免捕获后的虚拟坐标进入面板。移动 `dt` 上限为 0.1 s，每帧含最小化期间刷新时钟；失焦或最小化不移动并结束观察。保留 3:2 留边、最小化跳过绘制、可选颜色/深度自检。App 持有 Camera、CameraController、CameraSettings、Scene、UI、Mesh 和 Shader，析构时先在当前上下文内销毁 UI，再释放 Mesh/Shader，最后销毁窗口并终止 GLFW；初始化失败也由同一路径清理。每个实例运行一次，拥有上下文或 GPU 资源的类禁止复制和移动。当前构建/启动结果和待手动验收项见 [08 执行记录](08-小项目拆分与模块化推进.md#7-执行记录)。

阶段安排：A 完成工程与输入，B 接入最小 UI，C 接入单帧保存，E 再加入拍照任务推进。下面的完整主循环是最终组织参考，不要求阶段 A 一次写完。

## 1. 需要实现什么

| 功能 | 实现方法 |
|---|---|
| 创建窗口与上下文 | GLFW 创建 OpenGL 3.3 Core 上下文，然后加载 GLAD |
| 初始化资源 | 创建着色器、几何体、相机、渲染目标，之后加入 UI |
| 每帧更新 | 计算时间差、收集输入、更新参数、渲染、交换缓冲 |
| 输入协调 | App 判断相机输入是否可用，CameraController 读取键鼠并操作 Camera，界面交互交给 UI |
| 资源路径 | 使用明确的资源根目录，构建时复制资源或传入路径 |
| 正常退出 | 在 OpenGL 上下文销毁前释放纹理、缓冲、程序与 UI |
| 错误提示 | 输出窗口创建、着色器编译、资源加载和保存错误 |

## 2. 第一个版本怎么搭

复用当前 `.slnx/.vcxproj` 和 `Dependencies.props`，按小项目补充源码并同步登记工程与筛选器；当前不迁移 CMake。P00 已复验固定机位立方体，P01 已拆出 App/Mesh，P02 已接入 Camera/Scene，P03 增加 Dear ImGui 1.91.9b，依赖脚本按固定版本与 SHA256 获取源码。图片写入、JSON 等依赖留到对应任务。

初始化顺序：

```text
初始化 GLFW → 设置上下文要求 → 创建窗口
→ 将上下文设为当前 → 加载 GLAD
→ 查询实际版本 → 创建 OpenGL 资源 → 进入主循环
```

任何关键步骤失败都应退出并给出原因。着色器错误需要显示完整编译或链接日志，不能只写“渲染失败”。GLAD 的具体加载接口以采用的生成版本为准。

阶段 A 同时记录操作系统、编译器与 MSBuild、依赖版本与获取方式、显卡和驱动、构建及启动命令。实际配置见 [README](../Photograph/README.md)，骨架记录见 [P00/P01](验收/P00-P01/README.md)，移动取景记录见 [P02](验收/P02/README.md)。首次获取依赖可以联网，交付包启动不应临时下载资源。演示设备尚未确定时，将兼容性验收标为待验证。

## 3. 主循环怎样组织

以下为流程伪代码，`renderPreview` 等接口需要后续实现：

```cpp
while (!windowShouldClose()) {
    pollEvents();
    const double now = getTime();
    const float dt = float(now - previousTime);
    previousTime = now;

    ui.beginFrame();
    ui.editSettings(settings);       // 同一帧使用修改后的参数
    handleInput(camera, settings, dt);

    if (ui.requestedCapture() && !capture.isBusy())
        capture.start(makeSnapshot());

    capture.advance(renderer, postProcess, scene);
    renderer.renderPreview(scene, camera, settings, sceneTime);
    presentPhoto();
    ui.render();
    swapBuffers();
}
```

初期没有 UI 或 Capture 时，直接省略对应步骤。程序卡顿后可以限制用于移动的 `dt`，防止恢复窗口时相机突然跳很远；场景时间和拍照采样时间仍使用明确的时间定义，不依赖这个移动限幅。

Scene 提供 `evaluateAt(time)`，Renderer 在预览时间或拍照样本时间调用它，不能只靠每帧累加物体位置。

## 4. 输入如何分配

- WASD：前后左右移动；需要时加上下移动按键。
- 当前键位为 WASD 移动、Q/E 下降/上升、取景器内右键观察、R 只复位机位、取景器内滚轮变焦、Esc 退出（UI 占用键盘时先交给 UI）。捕获鼠标后立即建立坐标基准；机位更新要求鼠标处于取景器或观察已开启，且 UI 未捕获输入。
- 按住右键且鼠标位于取景器：旋转观察方向。
- 松开右键：正常操作参数面板。
- UI 捕获键盘时，不处理相机移动；UI 捕获鼠标时，不触发相机转动或点击对焦。
- 从面板进入观察模式时，在启用光标捕获后立即读取鼠标位置作为基准，避免把进入前的位移用于转向。
- 若取景器嵌在 UI 窗口中，需要专门判断它是否悬停、是否有弹窗覆盖，不能仅依赖一个全局鼠标捕获标志。

当前 CameraController 保存 `mouseLookActive` 和上一帧鼠标坐标，提供 `update(window, camera, dt)`、`startMouseLook(window)`、`stopMouseLook(window)`、`resetPose(window, camera)`、`isMouseLookActive()`。它不注册回调、不持有窗口或 Camera，不创建 GPU 资源；App 在窗口失焦或最小化时跳过更新并释放鼠标。

P03 已由 App 根据 UI 捕获状态和真实取景矩形分配输入；若 UI 接管观察，调用 `stopMouseLook()` 释放鼠标，重新进入时建立基准。焦距滑块、预设和取景器滚轮共用 CameraSettings 校验；复位按钮只产生请求，由 App 操作机位和设置。点击对焦、后续参数编辑和拍照请求不并入 CameraController。

GLFW 回调只记录事件或转发给输入层，不建议在鼠标回调里执行完整渲染或保存文件。

摄影界面完整键位见 [07 的 PC 操作建议](07-界面与验收.md)。在该界面接入后，将滚轮、方向键、F 和 Enter 转为变焦、参数编辑、中心对焦和拍照请求。每条事件只能消费一次；UI 文本编辑和弹窗优先，其次是被命中的控件和取景器。连续移动使用按住状态，改档与拍照使用按下沿。窗口失去焦点时清除持续输入与观察拖动，重新进入观察时重置鼠标基准。

## 5. 窗口尺寸和高 DPI

窗口逻辑尺寸、实际 framebuffer 像素尺寸、照片纹理尺寸是三个数。显示时根据 framebuffer 尺寸设置 viewport；鼠标位置按照取景器实际矩形换算到照片像素。

窗口最小化导致 framebuffer 为零时，跳过显示渲染，不创建零尺寸 FBO。首版可以固定照片为 900 × 600 等 3:2 尺寸，窗口缩放只改变显示大小。

## 6. 完成条件

- 能从干净构建目录编译、启动、退出。
- 从不同工作目录启动仍能找到着色器和资源。
- 修改窗口尺寸、最小化、恢复不会崩溃。
- 资源加载失败时能知道具体文件和原因。
- 退出时 OpenGL 资源在上下文仍有效时释放。
