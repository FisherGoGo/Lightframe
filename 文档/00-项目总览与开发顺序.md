# 项目总览与开发顺序

这组文档描述相机模拟器的目标、开发任务和职责边界。早期“只有方案、各阶段尚未开始”的说明是历史起点；2026-10-12 已完成 P00 基线复验、P01 App/Mesh 骨架拆分及 P02 Camera/Scene 自由取景。阶段 A 的本机功能验收通过，可移动、转向、复位并绘制多物体场景；课程演示设备兼容性仍待验证。B～G 尚未开始。最新状态与证据集中在 [08 的执行记录](08-小项目拆分与模块化推进.md#7-执行记录)。后续未实现的类、接口和示例仍属于计划。

目标：在三维场景中移动、取景，调节焦距、光圈、快门、ISO 和对焦距离，生成可以解释参数效果的照片。

## 1. 需要哪几个部分

| 部分 | 解决的问题 | 详细说明 |
|---|---|---|
| App 与输入 | 程序怎样启动、每帧怎样运行、输入给谁 | [01-工程与主循环](01-工程与主循环.md) |
| Camera 与参数 | 从哪里看、取景范围多大、使用什么摄影参数 | [02-相机与摄影参数](02-相机与摄影参数.md) |
| Scene 与资源 | 拍什么、怎样摆放、怎样运动 | [03-场景与模型资源](03-场景与模型资源.md) |
| Renderer | 怎样把三维场景画成颜色和深度纹理 | [04-渲染与帧缓冲](04-渲染与帧缓冲.md) |
| PostProcess | 怎样实现曝光、景深和噪声 | [05-成像与后处理](05-成像与后处理.md) |
| Capture | 怎样模拟快门时间并保存照片 | [06-拍照与文件保存](06-拍照与文件保存.md) |
| UI 与实验 | 怎样调参数、复现对比、验证功能 | [07-界面与验收](07-界面与验收.md) |

这里的“模块”是职责，不要求每个模块都成为一个复杂类。初期可以用一个主文件和几个辅助函数，功能稳定后再拆文件。

摄影参数统一由 `CameraSettings` 保存，Camera 计算投影时读取它的焦距和传感器尺寸。预览使用当前设置，拍照使用开始时复制的快照；快照是一次任务的固定输入，不是另一份可编辑设置。

### 交付范围

| 层级 | 包含内容 | 交付定位 |
|---|---|---|
| 最低可交付版本 | 简单几何场景、移动与变焦、基础光照、HDR 与曝光、最小 UI、PNG + JSON 保存、实验 A 和曝光对照、运行说明 | 阶段 C 后形成的保底版本；光圈与快门暂只影响曝光，不能宣称已完成全部摄影模拟 |
| 目标交付版本 | 最低版本 + 点击对焦、基础景深、确定性动画、多时间采样拖影、简化噪声、三个可复位实验、打包与报告 | 当前计划的完整目标；允许使用布置完整的几何实验场景 |
| 加分功能 | Assimp 模型导入与正式资产、景深分层与边缘改善、JSON 拍摄配置回放、阴影、直方图、多边形散景、高分辨率导出 | 目标版本验收通过且有剩余时间后选做 |

默认不做真实照度标定、完整传感器物理模型、镜头畸变、碰撞、骨骼动画或多线程 OpenGL。课程若强制要求模型导入等功能，应在开工前调整上述层级。

## 2. 各部分怎样配合

```text
键盘 / 鼠标 / UI
    → App 协调输入
    → 更新 Camera 和 CameraSettings

Scene 按时间生成物体变换
    + Camera 提供 view / projection
    → Renderer 输出线性 HDR 颜色 + 深度
    → PostProcess 计算景深
    → 预览：直接进入曝光处理
      拍照：多个时刻的结果平均后进入曝光处理
    → 曝光 + 简化噪声 + 色调映射 + 显示编码
    → 照片纹理
        → Capture 导出 PNG 和 JSON
        → 显示取景器，再绘制 UI
```

Camera 提供参数和矩阵；Renderer、着色器和 Capture 执行成像。把所有效果都塞进 Camera，会使输入控制、GPU 资源和文件保存互相牵连。

## 4. 开发顺序

| 阶段 | 前置条件 | 实现内容 | 进入下一阶段前的证据 |
|---|---|---|---|
| A | 编译与演示环境已确认 | 工程、简单场景、深度测试、基础 Camera | 干净构建成功；可移动、转向、复位 |
| B | A | 焦距、最小 UI、实验 A 预设 | 固定机位的 24/85 mm 对照；变焦不改变位置 |
| C | B | 基础光照、FBO、HDR、曝光、单帧 PNG + JSON 保存 | 曝光数值检查通过；导出方向、颜色、参数匹配；最低版本可运行 |
| D | C | 深度重建、点击对焦、CoC 调试、基础景深、实验 B | 已知距离测量通过；等曝光的光圈与对焦对照 |
| E | D | 时间动画、固定快照、多时间采样、分帧进度、实验 C 拖影部分 | 静态样本亮度稳定；运动拖影对照；预览修改不污染拍照 |
| F | E | 简化噪声、实验 C 噪声部分、目标功能联调 | 固定种子复现；三个实验均可一键复位并导出 |
| G | 所选交付层级的功能完成 | 缺陷修复、性能记录、打包、报告 | 通过 07 的相应交付检查，并在演示设备运行 |

学习顺序对应：Coordinate Systems → Camera → 基础 Lighting → Framebuffers → Gamma Correction / HDR → 深度与景深 → 时间采样。Model Loading 在核心流程稳定后按需学习。

每一阶段先用简单场景验证，再接入正式资源。不要同时修改相机、光照、后处理和模型加载，否则画面出错时很难定位原因。

### 排期与取舍规则

- 截止时间、人数、OpenGL 熟练度、课程评分要求和演示设备尚未确认，因此暂不承诺具体日期。开工前补齐这些条件，再为 A～G 填负责人和时间预算。
- 总可用时间暂按约 80% 功能开发、20% 验收与交付预留；这是排期起点，不是已测工时。每阶段结束后按实际进度重估。
- 阶段 C 完成后保留一个可运行的保底版本；后续每阶段也保留构建说明、照片、参数和已知问题。
- 进入交付预留时间后停止新增功能。先取消加分项，再评估目标版本是否来得及；若只能交最低版本，明确说明缺少景深、拖影或噪声，不能把它标为目标版本完成。
- 景深边缘改善不阻塞阶段 E；正式模型不阻塞任何核心阶段。若基础景深或时间采样无法满足验收，先缩小场景和参数范围定位问题，不用扩展功能掩盖问题。

## 5. 全项目共用约定

- 世界空间 1 单位 = 1 m；光学公式统一使用 mm，距离进入公式前乘 1000。
- 使用常规 OpenGL 透视深度：NDC 深度为 -1～1，深度纹理为 0～1；首版不采用反向深度或正交投影。
- 传感器 36 × 24 mm，照片比例 3:2；窗口变化只影响展示区域，不改变传感器尺寸。
- 光圈保存 f 值，快门保存秒数，焦距保存 mm，对焦距离保存 m。
- 所有光照、景深和时间平均在线性 HDR 图像上计算；最后执行一次显示编码。
- UI 不参与成像，不出现在导出照片中。
- 拍照使用固定快照：机位、参数、场景时间、随机种子在拍摄开始时确定。
- 首版预览显示瞬间画面，运动拖影只在拍照时计算。
- 目标版本固定照片为 900 × 600；预览与导出使用相同成像尺寸。实验预设同时固定机位、场景配置、时间、摄影参数、效果开关与种子。
- 本文中的“首版”指对应功能的第一轮实现，不意味着该章全部功能都属于最低交付范围；范围以本总览为准。

## 6. 从哪里开始

### 摄影交互参考：Lushfoil Photography Sim

本项目将《Lushfoil Photography Sim》作为摄影界面与操作流程参考，调研依据和转化方案写在 [07 的第 7 节](07-界面与验收.md)。重点借鉴取景时直接调整参数、明确的对焦反馈、参数效果说明与拍摄结果反馈。正常摄影界面以取景器为主体，实验与调试面板按需展开。

参考内容随现有阶段接入：B 做取景与变焦，C 做曝光档位和单帧拍照反馈，D 做点击/中心对焦，E/F 做进度与长曝光说明，G 整理布局和提示。这些操作使用现有 CameraSettings、ViewportRect 与 Capture 快照，不另建一套相机参数。

继续采用当前 C++/OpenGL 工程；游戏使用 UE5 不构成迁移引擎的理由。开发者公开的长曝光合成方法与现有多时间采样方向相符，技术转化见 [06](06-拍照与文件保存.md)。A/S 自动曝光、横竖拍、实体机身、举起动画、白平衡、闪光灯与环境控制为选做项，核心摄影流程验收后再考虑。目标版本先完成 M 模式、取景器、对焦、参数调整和 PNG + JSON 保存。

先看 01、02、03，完成“窗口里有几个立方体，能移动和变焦”。之后读 04 和 05 的曝光部分，再实现 06 的单帧保存。景深、多时间采样和噪声放在后面。

每完成一阶段，保存截图、参数和已知问题。实现指南描述的是计划；完成状态另行记录，避免把文档中的示例当成已经实现的功能。

阶段记录建议使用：`阶段 / 状态（未开始、进行中、已验收、阻塞）/ 负责人 / 计划与实际耗时 / 验收证据 / 已知问题 / 下一步`。当前 A 本机功能已验收（P00/P01/P02 已验收，演示设备仍待验证），B～G 未开始；一个小项目完成不代表整个阶段完成。详细状态维护在 08。
